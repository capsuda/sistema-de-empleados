# OBJETIVO
Construir una aplicación web donde el personal de RRHH y los administradores gestionen empleados y sus documentos (contratos, cédulas, títulos, etc.) desde un panel. Los empleados pueden iniciar sesión y ver únicamente su propia información y documentos.

# STACK (ya instalado en el proyecto, no cambies nada sin consultarme)
- Next.js (App Router) + TypeScript estricto, con carpeta `src/`
- Tailwind CSS + shadcn/ui (componentes ya agregados)
- PostgreSQL en Neon con Drizzle ORM (`drizzle-orm`, `@neondatabase/serverless`)
- Better Auth para autenticación y sesiones
- React Hook Form + Zod para formularios y validación
- TanStack Table para las tablas del panel
- Cloudflare R2 (API compatible con S3, `@aws-sdk/client-s3` y `@aws-sdk/s3-request-presigner`) para los archivos
- `file-type` para validar el tipo real de los archivos
- Upstash Redis + `@upstash/ratelimit` para rate limiting
- Despliegue final en Vercel

# MODELO DE DATOS (PostgreSQL)
- Tablas de autenticación: las que genere Better Auth (user, session, account, verification). Agrega a la tabla de usuario un campo `role` con los valores: `admin`, `rrhh`, `empleado` (por defecto `empleado`).
- `departments`: id, name (único).
- `employees`: id (uuid), user_id (referencia opcional al usuario), department_id, first_name, last_name, national_id (único), job_title, hire_date, status (`activo` | `inactivo`), created_at.
- `document_types`: id, name, is_required (boolean).
- `documents`: id (uuid), employee_id (cascade), document_type_id, storage_key, original_filename, mime_type, size_bytes, uploaded_by, expires_at (fecha opcional), created_at.
- `audit_logs`: id, user_id, action, entity, entity_id, created_at.
Define todo en `src/db/schema.ts` con Drizzle, con relaciones, índices en claves foráneas y tipos exportados.

# REGLAS DE SEGURIDAD (obligatorias en todo el código)
- Toda verificación de permisos se hace en el SERVIDOR (server actions y route handlers), nunca solo ocultando botones.
- Prevenir IDOR: un empleado no puede acceder a datos ni documentos de otro cambiando un ID. Centraliza las reglas en `src/lib/permissions.ts`.
- Validar con Zod toda entrada en cada endpoint y server action.
- Tipos de archivo permitidos: PDF, JPG, PNG. Tamaño máximo: 10 MB. Validar el tipo real del archivo, no solo la extensión ni el mime_type que envía el cliente.
- Bucket R2 privado. Nunca exponer URLs públicas. Generar el `storage_key` en el servidor, con un nombre aleatorio, nunca con el nombre original del archivo.
- Rate limiting en login y en la generación de URLs de subida.
- Ningún secreto en el código: todo en variables de entorno.
- Agregar cabeceras de seguridad (CSP, HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy) en `next.config.ts`.
- Mensajes de error genéricos hacia el usuario (sin filtrar detalles internos).
